# IdeaFlow 人工验收

使用包含计划审批和规格复审的分支 `feat/orchestrator-spec-gate`。在仓库根目录打开两个 PowerShell 终端。用不同的输出目录保留各次验收结果。

## 启动需求与编排工作台

在终端 1 启动需求工作台：

```powershell
Set-Location modules/requirements
..\..\.venv\Scripts\python.exe -m ideaflow.server --port 18081 --out ../../runs/manual-requirements
```

在终端 2 启动编排工作台：

```powershell
.\.venv\Scripts\python.exe modules/orchestrator/python/agent.py serve --mock --port 18080 --out runs/manual-orchestrator
```

## 验收 1 规格阻断与人工复审

1. 打开需求工作台的[紧凑版二手书案例](http://127.0.0.1:18081/?mode=spec&case=campus-books-tight&auto=1)，看到规格 v2 待人工决策且有一条工期阻断。
2. 下载当前规格 JSON。到[编排工作台](http://127.0.0.1:18080/)粘贴并启动。预期页面提示规格需要人工决策，任务数为 0。
3. 回到需求工作台的「审查与修订」，选择 A 延长到页面列出的工期，填写处理人和理由，点击「提交回答并复审」。预期规格升至 v3，快照升至 v2，审查阻断为 0。
4. 再次下载规格 JSON。将新规格粘贴到编排工作台并启动。预期显示待批准 v1，任务已列出且运行数为 0。

工期冲突的 B 选项使用既有规则继续裁剪，修订后仍有阻断时会展示新一版的审查。规则无法再裁剪时，保留当前版本并提示人工处理。接受风险和其他需要取舍的问题使用人工修订，再提交复审通过的规格。

## 验收 2 计划退回与批准

1. 在待批准时点击「退回计划」，填写理由并提交。预期计划升到 v2，规格版本沿用 v3，运行数仍为 0。
2. 在决策记录中核对 `return`、退回理由和被退的版本 v1。输出目录中的 v1 计划 JSON 与 v2 计划 JSON 均可读取。
3. 批准 v2。预期页面显示已批准 v2，依赖满足的任务才开始运行。
4. 验收「退回规格」时，在计划待批的实例粘贴已复审通过的同一规格的下一版，并填写原因。预期规格和计划都升版，旧版可查，新计划重新待批。

## 验收 3 交付确认

1. 对当前运行的 AI 任务选择「完成」并点击「提交回报」，按调度出现的任务逐一回报。若页面提示人工任务，按其要求处理。
2. 全部任务结束后，交付面板出现待确认清单。核对任务和产物 ID。
3. 点击「确认交付」。预期实例完成，交付记录和决策记录都有确认人及时间。
4. 另启一个 Mock 编排实例，用另一个 `--out` 目录跑到交付待确认，选择「退回」并填写理由。预期实例进入阻塞，交付面板和决策记录都能看到理由。

## 验收证据

- 需求运行目录保留 `spec.v2.json`、`spec.v3.json`、`snapshot.v2.json`、`answer.v2.json` 和同版审查。
- 编排输出目录保留分版本计划、`delivery.json` 和 `decisions.jsonl`。
- API 会拒绝旧规格引用和重复回答。自动化回归包含这两个分支，也覆盖从阻断到交付完成的 HTTP 链路。
